# Audit entry point: native GEMM and its measurement process

The readability cleanup changes organization, names, comments and host helper
boundaries, **not the GPU algorithm**. Original minified source snapshots in
`results/` remain untouched: they are the evidence for the original timings.
Fresh cleanup builds/results use a separate `readable` namespace. A later
intentional [branch-only optimization](BRANCH_CLEANUP.md) uses `branch-clean`;
its ordering proof is separate from the historical byte-identical cleanup.
The next [single-MFMA move](MFMA_FIRST.md) has its own exact-move audit and
fresh `mfma-first` builds, rather than relabeling the branch-only records.
The separate [FP8 B producer](FP8_B.md) changes packing/producer work but
preserves compute/raw-read/fence order. It regresses low grids and remains an
experimental variant, not the default. Its FP16 host bridge is GPU-byte-identical.

The default is **tile128,StageK32,ordinary GEMM,linear LDS mapping**. Other tile/

## 2. Logical operation and storage

The ordinary kernel computes `C[M,N] = A[M,K] * B[K,N]`, FP16 inputs and FP32
accumulation/output, alpha1/beta0. One CTA owns one output tile, accumulates
all K, then stores C once. No split-K or atomics. Packed tails are zero; C
stores are masked to actual M,N. K0 writes zero C on the GPU.

The harness keeps original row-major **integer units of1/16**, not packed
fragments, in `TestMatrices`. The nine values[-4..4]/16 are exactly FP16.
`reference_dot()` uses those original coordinates and int64 products, then
divides by256. It does not decode or reuse the GPU packing logic.

Packing is performed by `pack_operand()` outside GEMM timing:

```text
[StageK chunk][half-CTA row/column panel][K8 fragment][micro-pair][lane][4 dwords]
```

For selected128, each panel covers64 rows of A or64 columns of B. One lane's
16-byte vector contains two MFMA microfragments: words0/1 for the first,
words2/3 for the second. `position` identifies the logical row/column;
`first_inner` identifies K. Both formulas are written explicitly in the packer.
The resident diagnostic instead repeats the first padded StageK fragment;
it has its own explicit oracle and is rejected by the normal benchmark runner.

## 3. GPU addressing and register map

Four compute waves form a2x2 grid of64x64 output tiles. Producer assignment
is different: waves0/1 load A's halves, waves2/3 B's halves. Read both the
producer and consumer address expressions in `native_gemm`; do not assume
that each wave loads only the operand it later computes with.

Selected128/K32 fixed VGPR map, directly generated by `Configuration`:

| VGPRs | Role |
|---|---|
|v0..7|q0 raw operands: A0/A1 then B0/B1, two registers/microfragment.|
|v8..15|q1 raw operands.|
|v16..23|q2 raw operands.|
|v24..31|q3 slot A.|
|v32..39|q3 slot B/spare.|
|v40..41|64-bit moving global source pointer.|
|v42..43|Alignment gap, included in clobbers.|
|v44..59|Four prefetched DWORDx4 producer packets.|

Inputs such as LDS bases are compiler-allocated outside the fixed clobber
range. `c0..c3` are four16-element FP32 accumulator vectors constrained to
AGPRs. F16 in C++ means **sixteen floats**, not a half scalar.

Generated wrapper operand names are deliberately stable and short:
`lo/hi` = initial global pointer, `step` = final stage pointer increment,
`dst` = producer LDS address, `alo/blo` = current wave's A/B LDS read bases.
The fixed4 KiB pointer bumps inside a large panel are already subtracted
from `step` by the caller. The generated wrapper text is kept byte-identical;
read the named emitter methods for the algorithm rather than treating its
mechanical C++ string serialization as the design description.

## 4. Synchronization invariant to check

`emit_stage()` has two different barriers:

1. **Retire:** LGKM0 then barrier, before any wave overwrites the single LDS
   buffer. All current operands have already been read into registers.
2. **Publish:** after writing the next stage and issuing the first quarter of
   current math, LGKM0 then barrier makes all next-stage LDS data readable.

After the head VM0, current q0/C00 now issues before LDS stores/global
prefetch; the rest of q0 stays after them. This is the single intentional
move documented in MFMA_FIRST.md. The publish point does NOT drain the
future global prefetch: VMEM has its own counter. VM0 is at the consumer point for the already-prefetched panel,
not after every global instruction.

Only consumed q0/q1/q2 slots are overwritten by next-stage reads. Next q3
uses the spare slot while current q3 remains live. Two phase labels swap
which fixed slot holds q3; no payload register copy implements the swap.
The final stage consumes its operands without reading beyond packed K.

In `loop.txt`, verify two-stage counts/wave:32 MFMA,8 global x4,8 LDS writes,
16 LDS reads,four CTA barriers. Branch cleanup keeps these counts but removes
the per-stage boundary checks and fall-through phase jump; only a three-
instruction subtract/compare/backedge remains. One-to-three final stages are
separate; see BRANCH_CLEANUP.md before interpreting static whole-body counts. `inspect_code.py` checks these in the actual
embedded object's backedge, and separately checks startup/tail totals,
private memory and forbidden timed accumulator/conversion/spill operations.

## 5. What the checks prove (and do not)

`make_reference()` chooses full reference when M*N*max(K,1)<=30,000,000;
otherwise it uses2048 seeded samples plus row/column microtile boundaries
and matrix edges. The sampled count is recorded. `verify_output()` also
scans **every C value finite after NaN poisoning** and checks32 guards.
Do not call that a full numerical reference for the large matrices.

Exact equality is justified only for this integer/16 domain,K<=65536.
No arbitrary FP16 NaN/Inf/subnormal or real-model numerical guarantee is
claimed. Inputs are actual non-repeating packed matrices; the final timed
suite never uses the repeated-fragment diagnostic.

## 6. Timing and efficiency definitions

- Full HIP-event time includes accumulator setup, pipeline and final C stores.
  Packing/H2D/reference/checking are excluded. No hidden graph batch.
- Binary stamp order: `[CTA][wave][core_begin,core_end,steady_begin,steady_end]`.
- Core spans compare clocks **within one CTA**; grid time uses common steady
  timestamps across CUs. The Python runner independently recalculates them.
- `median_cta_share_of_cu_peak` uses one CTA's executed work/own core span.
  It is not whole-GCD utilization when several CTAs share a CU.
- `global_clock_adjusted_efficiency` divides useful full-event TFLOP/s by
  `104 *1024 *measured_core_MHz /1e6`. This is an operating-point estimate,
  not nominal1700 MHz or a clock-locked peak.

`analyze.py` uses a predetermined long-K launch/repetition/round for overlap,
not whichever sample gives the highest overlap. Ends precede starts at equal
ticks, so its half-open-interval count is conservative at ties. This proves
body overlap, not exact allocation timestamps or one-to-one CTA/CU mapping.

## 7. Follow the experiment history

`DESIGN_LOG.md` links each phase's source/build snapshots and measured binary:
initial -> null register-pair/LDS-XOR hypotheses -> verified resident diagnostic
-> earlier publication/rolling reads -> K64 regression -> matched full-grid
choice of128/K32. The losing candidates remain explicit. No original result
was rewritten as a fresh measurement after cleanup.

Old manifests name the live paths used at build time. Those paths now contain
readable code, so `verify_artifacts.py` checks source entries against their
**archived snapshot**, while native entries still name preserved original
executables. Stage64's documented source recovery was checked against its
recorded SHA256, not inferred from approximate source similarity.

```sh
python3 research/native-gemm/run.py --output <fresh-results-directory>

```

The historical cleanup audit compares all8 generator outputs byte-for-byte, all144
packed operand vectors for18 logical matrix/seed cases, original/new reference
dots, and actual GPU `.text` for both GEMM candidates and bank-control kernels.
`results/cleanup-audit/` records that proof; `results/readable/` records the

`results/branch-clean/` separately record the intentional branch change.

change; the proof specifically identifies the unchanged GPU instruction bytes.
Use fresh build paths when changing source; never overwrite measured historical
binaries just to make a manifest pass. No new package or formatter dependency.
